1 · 증분 적재 설계

전역 MAX(Date)로 자르면 중단 후 일부 티커가 영구히 뒤처진다. Q-SEED는 청크 시작일을 그 청크에서 가장 이른 티커별 last_date에 맞춘 뒤, 끝나면 (Ticker, Date) 중복을 제거하고 자동 gap repair를 돌린다.

단계 Naive Q-SEED
시작일 전역 MAX(Date) min(ticker last_date in chunk)
중단 후 재실행 이미 최신인 청크만 기준으로 뒤처진 티커를 놓침 낡은 티커가 청크 시작일을 끌어내림
비용 적음 같은 청크의 최신 티커를 조금 더 받은 뒤 dedup
마무리 없음 auto-repair → --check-gaps / --repair-gaps

모드

명령 언제
--build-db 테이블 초기화 후 전체 재적재
--update-db 티커별 last_date 증분 + 기본 자동 복구
--check-gaps 수집 없이 리포트만
--repair-gaps 뒤처진 티커만 재수집
--no-gap-repair 증분만, 자동 복구 끔

문서에 솔직히 적을 함정

last_date.txt는 진실 공급원이 아님

파일은 전역 최신일이다. 증분 시작일의 진실은 DuckDB 티커별 MAX(Date)다.

중간 구멍은 증분이 못 고친다

마지막 날짜가 최신이면 중간에 빠진 날은 다시 받지 않는다. 아래 interior hole로 연결한다.

수정주가 재작성 시 어느 행이 남는가

deduplicate_raw_stocks는 Unknown Market만 뒤로 밀어 한 행을 남긴다. 최신 수집 행을 항상 이기게 하지는 않는다.

산출물. docs/design/incremental-load.md — 시퀀스 세 칸 + pytest 하나: A는 1/20, B는 1/10인 청크의 시작일이 2024-01-10인지 단언. 코드: src/pipelines/stock_pipeline.py, data-pipeline.md.

2 · Gap detection

detect_gaps는 시장별 MAX(Date) 대비 lag_days > gap_tolerance_days(기본 5)인 티커만 본다. “공백 탐지가 있다”가 아니라 공백을 다섯 종류로 나눈 뒤 어떤 것만 잡는지가 깊이다.

공백 종류 예시 지금 대응
Tail lag 청크 실패로 한 종목만 3주 전 탐지 --repair-gaps, incremental 후 auto-repair
달력 왜곡 미국 7/4 vs 한국 7/6 회피 전역 max가 아니라 시장별 max + tolerance 5일
휴장 과대계상 설날·추석을 weekday가 결측으로 봄 힌트만 dbt missing_rate는 거래소 캘린더가 아님
Interior hole 중간 5일 비고 끝은 최신 미탐지 구현하지 말고 ADR에 알려진 한계로
상폐 · 신규 · 정지 last_date가 멈춤 lagging으로 잡힘 repair가 비면 no_data_list.txt
경계값 계약

비교는 >이다. lag 5일은 제외, 6일은 포함. 문서와 테스트를 같게 잠근다.

KR / US fixture

같은 전역 날짜라도 Market이 다르면 오탐하지 않는지. 전역 max를 쓰면 실패하는 케이스를 테스트로 남긴다.

구현하지 말 것. 거래소 공휴일 캘린더 엔진. 깊이의 증명은 한계를 알고 있음이지 캘린더 SaaS가 아니다. 코드: src/repositories/gap_detector.py, 대시보드 3_Freshness_Gaps.py.

3 · dbt 계보와 테스트

1단계는 “테스트가 깨지면 CI가 실패한다”였다. 2단계는 무엇이 무엇에 의존하고, 어떤 실패가 어떤 의미인지를 보여 준다. 무거운 int_stocks__daily_returns / fct_stocks__price_factors는 점선 — CI 분 단위를 깨지 않으려고 기본 꺼 둔다.

Source: dbt/models/stocks · CI는 stocks+market만 build. int/fct는 enabled: false.

테스트 카탈로그

테스트 모델 실패 시 의미
unique Ticker+Date stg_stocks__raw_stocks 증분 dedup 실패 또는 이중 적재
accepted_values country/currency dim_stocks__market 시장 매핑 누락
sector_status enum dim_stocks__security enrichment 계약 위반
not_null Date/Ticker/Close staging 원천 적재가 빈 키를 넣음
로컬 증거. make dbt-ci — 합성 DuckDB, 네트워크 없음, data/stocks.db를 덮지 않음. 선택: dbt ls --select +rpt_stocks__freshness+. dbt Cloud / 공개 docs 사이트는 하지 않는다.

4 · Docker 재현성

지금 Compose는 sleep infinity와 소스 bind-mount를 쓰는 개발 셸이다. “이미지 한 장으로 연구 결과가 비트 동일”이라고 쓰면 거짓이다.

lockfile + pytest

bind-mount 없이 이미지 코드와 uv.lock으로 pytest와 make dbt-ci만. 네트워크 시세 없음.

재현되는 것 / 안 되는 것

재현됨 재현 안 됨
의존성 (uv.lock, --frozen) yfinance 라이브 바 데이터
pytest 합성 백테스트 로컬 data/stocks.db (named volume)
dbt on ci_stocks.db 대시보드가 보여주는 실제 웨어하우스
증명 레시피. 호스트 make test와 컨테이너 uv run pytest가 같은 테스트 수를 통과한 로그 두 줄이면 충분하다. 이미지에 DuckDB를 굽거나 프로덕션 오케스트레이션은 하지 않는다.

5 · 백테스트 정확성

정확성을 케이스 스터디 CAGR에 맞추는 일이 아니다. 알려진 편향이 코드에 없음을 작은 fixture로 증명한다. 엔진은 이미 리밸런싱일 다음날부터 수익을 반영하고 (Date > start_date), 비용은 구간 첫날에 turnover * bps / 10000이다. 잠그는 테스트가 없다.

# 계약 단언
1 Lookahead 리밸런싱일 T 종가로 포지션, 수익은 T+1부터. 2종목×4일 손계산과 일치
2 가중치 long_short signed sum ≈ 0, long_only ≈ 1
3 비용 턴오버 1.0 · 10bps면 리밸런싱 다음날 수익이 정확히 10bps 차감
4 결정성 같은 prices·factor 두 번 → 같은 CAGR/MDD
5 빈 유니버스 min_observations 미달이면 빈 결과이지 예외 아님
6 분위 동점 rank(method="first")라 같은 팩터값이어도 5분위로 나뉨
CI 골든으로 넣지 말 것. 케이스 스터디 +7.63% 같은 실데이터 숫자는 빈티지 문제다. 1단계에서 “문서 숫자는 산출물에서 옮긴다”로 이미 닫혔다. 코드: src/backtest/engine.py, KR 백테스트 케이스.

6 · 설계 의사결정 문서

architecture.md는 구조 설명이다. 여기서 필요한 건 Context → Decision → Consequences → Rejected alternatives. docs/adr/에 페이지 반짜리 7개면 위 스트림과 1:1이다.

ID 제목 핵심 한 줄
001 Warehouse SoT 분석·대시보드는 yfinance를 치지 않고 DuckDB를 읽는다
002 증분 시작일 전역 max가 아니라 청크 내 min last_date
003 Gap 기준 시장별 최신일 + 달력 5일. 거래소 캘린더는 아직 없음
004 dbt on DuckDB 로컬 엔진. BigQuery/Spark는 핵심 경로 아님
005 동일가중 기본 최적화는 별 경로. equal_weight는 opt_max_assets를 안 탄다
006 재현 범위 git SHA + DuckDB fingerprint. 시세 API 비트 재현 포기
007 Docker 역할 개발 셸. 재현 증명은 lockfile + pytest/dbt-ci

권장 순서

의존성이 한방향이다. ADR이 판단을 잠그고, 문서가 주장을 적고, 테스트가 그 주장을 잠근다.

  • ADR 초안 7개 — 판단과 버린 대안부터 적기. docs/adr/
  • 증분 설계 — docs/design/incremental-load.md + 청크 min-date pytest
  • Gap — 문제/한계 문서 + 경계값·시장별 fixture
  • 백테스트 invariant 6개 — 엔진 계약의 코드 코어. tests/test_backtest_engine_invariants.py
  • dbt 계보 — docs/design/dbt-lineage.md + make dbt-ci 로그 스냅샷
  • Docker 두 모드 — docs/design/docker-reproducibility.md + 컨테이너 pytest 로그
